## Planned implementation order

1. **Launch** — stable command-line modes, keyboard selection, open-all, missing-target behavior, process/shell invocation.
2. **ShellLink/AppUserModelID** — create/update group links, per-group identity, pinning, Windows shell integration, UWP/PWA activation.
3. **Icons** — extraction, explicit icon selection, cache invalidation, generated group icons, DPI-aware assets.
4. **Migration** — versioned model, legacy XML import, path repair, transactional writes, portable vs installed data locations.
5. **Native UI** — Windows-native configuration and flyout surfaces, layout, DPI, accessibility, errors, tooltips.
6. **Packaging/testing** — signed/reproducible artifacts, manifests, release channels, installation/uninstallation, Windows 10/11 matrix and end-to-end tests.

## Priority definitions

- **P0:** blocks a basic launch/save/pin workflow or can cause data/process damage.
- **P1:** compatibility or correctness issue that affects common Windows configurations.
- **P2:** important usability or supported-target feature.
- **P3:** optional polish, speculative scope, or documentation-only work.

## Acceptance gates by planned order

- **Launch:** no panic/crash for missing targets, repeated activation, empty groups, bad arguments, or any monitor geometry; launch plans are testable without starting processes.
- **ShellLink/AppUserModelID:** generated links open the intended group, preserve per-group identity, update after edits, and pin correctly on Windows 10 and 11.
- **Icons:** every supported source has a deterministic extraction/fallback path; cache invalidation is tested after target/icon changes and at multiple DPI sizes.
- **Migration:** legacy `Category`/`ProgramShortcut` XML imports with exact element names, repairs known path issues, preserves ordering/arguments/working directory, and never destroys the source on failed migration.
- **Native UI:** all actions map to the existing controller boundary; long names, keyboard navigation, tooltips, DPI, monitor edges, missing files, and field-level errors are covered.
- **Packaging/testing:** release bundles contain the executable and required assets, carry version/manifest metadata, cleanly uninstall, and run a Windows 10/11 smoke matrix.
